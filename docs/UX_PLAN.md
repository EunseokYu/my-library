## 1. 판단과 검토 범위

핵심은 ‘서재를 꾸미는 경험’을 유지하면서 ‘찾기·기록하기·저장 확인’을 짧게 만드는 것이다. 새 기능보다 입력 유실을 먼저 막고, 등록과 감상 작성 흐름을 정리한 뒤 탐색 기능을 추가한다.

공개 사이트의 빈 서재·설정·통계·등록 화면을 직접 확인했고 소스에서 저장, 렌더링, 검색, 기록, 동기화 경로를 검토했다. 실제 계정 로그인, 실데이터, 유료 API 호출, 모바일 기기 실측, Supabase 서버 정책은 검증하지 않았다. 아래 ‘코드 확인’은 정적 분석 결과이며 실제 브라우저 재현 완료를 뜻하지 않는다. 속도 문제나 보안 취약점을 확정하지 않는다. 이 문서는 검토·구현 지시서이며 앱은 수정하지 않았다.

유지할 기본 정책: 완독 작품 중심, 작품당 하나의 기록, 현행 평점 0~5, 기존 책등 디자인·색·상징, 기존 JSON 백업 호환. 다판본 소장·재독 이력·읽는 중 기능은 별도 제품 결정으로 보류한다.

### 추가로 주의할 두 가지

- 계정 전환: `signedOut()`는 로컬 책과 API 키를 지우지 않고, 첫 동기화는 서버에 없는 로컬 책을 올린다. 다른 계정으로 로그인할 경우 기록이 섞일 가능성이 있는 구조다. 다계정 실험은 미실시. 제품 기능 확대 전에 계정별 로컬 공간 또는 ‘가져오기’ 선택 흐름을 별도 작업으로 검토한다. 실제 사용자 계정으로 실험하지 않는다.
- 동기화 충돌: 아직 전송하지 않은 로컬 책이 우선되는 정책이다. 같은 책의 두 기기 동시 편집을 자동 병합한다고 안내하면 안 된다. 재독/협업 기능을 추가할 때 충돌 정책부터 설계한다.

### 지금 새로 만들 필요가 없는 것

검색은 감상·문장까지 이미 포함한다. 태그 필터, 저장 실패 알림, 편집 취소 경고, 동기화 재시도, JSON 복원 미리보기, 검색 캐시, AI 일부 재호출 방지도 존재한다. 이를 새로 구현하기보다 빈틈과 노출 위치를 고친다. AI 자동화를 늘리거나 React/백엔드 전면 교체를 이번 개선의 전제로 삼지 않는다.

## 3. 실행 순서와 비용 절감 방식

1. **T0 기준점:** 브랜치/커밋과 기존 동작을 기록하고 작은 코드 지도를 만든다. 개발용 합성 도서 fixture와 네트워크 mock을 준비한다.
2. **T1 입력 보호:** U01·U02·U11. 재현 테스트를 먼저 만들고 수정한다. 가장 먼저 사용자가 체감할 안정성 개선이다.
3. **T2 최소 구조 분리:** 동작을 바꾸지 않고 CSS와 JavaScript를 추출한다. U01 수정과 대규모 파일 이동을 섞지 않는다.
4. **T3 등록·기록:** U03·U04·U07·U10. 기존 폼을 단순화하고 초안 보호 경로를 재사용한다.
5. **T4 탐색·저장 상태:** U05·U06·U08·U12. 공통 selector로 두 보기의 결과를 일치시킨다.
6. **T5 삭제 복구:** U09. 동기화 삭제 경쟁을 다루므로 별도 커밋/검증으로 격리한다.

T1까지 먼저 적용해도 가치가 있다. 각 단계는 완료 조건을 통과한 뒤 다음 단계로 간다. 한 번에 T0~T5 전체를 요청하지 않는다. 단계가 크면 같은 번호 아래 작은 커밋으로 나누되 작업 범위를 확대하지 않는다. 실제 배포는 로컬 검증 이후 사용자가 요청할 때 한다.

토큰 절약은 내용을 생략하는 것보다 재설명과 재작업을 줄이는 방식으로 한다:

- 이 명세는 저장소 `docs/UX_PLAN.md`로 한 번만 넣는다. 이후 ‘T3 진행’처럼 작업 ID로 요청한다.
- `CLAUDE.md`에는 불변 조건과 문서 경로만, `docs/CODEMAP.md`에는 파일·기능·주요 함수만, `docs/HANDOFF.md`에는 현재 상태/다음 작업만 적는다. 문서 복제 금지.
- 각 작업에서 전체 파일을 출력하지 않고 `rg`로 관련 심볼과 호출자부터 읽는다. 처음에는 전체 구조 확인이 필요하다.
- 테스트/에러 출력은 핵심만. 수행 안 한 테스트는 ‘통과’로 쓰지 않는다. 결과 답변은 변경·검증·남은 위험·다음 작업으로 짧게 한다.
- 채팅이 길어지면 HANDOFF를 갱신하고 새 대화에서 이어간다. 이전 대화 전체 복사 금지.
- 커밋은 기능 또는 결함 단위. 포맷 전체 변경·이름 변경·로직 변경을 한 커밋에 섞지 않는다.
- 시간·토큰 절감률 수치는 측정하지 않았으므로 약속하지 않는다.

## 4. Claude 최초 공통 프롬프트

저장소를 연결하거나 파일 작업이 가능한 Claude 환경에 저장소를 열고 이 문서를 첨부한다. 일반 채팅만 가능하면 변경 파일을 내려받아 직접 적용해야 하므로 저장소 접근 환경이 효율적이다.

```text
첨부 문서를 docs/UX_PLAN.md로 저장하고, eunseokyu/my-library 저장소의 사용성을 단계별로 개선해라. 우선 T0만 수행해라.

목표: 입력 유실 방지, 책 등록과 감상 작성 단순화, 탐색 개선, 이후 기능 추가와 유지보수 비용 절감.
명세의 기준 커밋은 7eea0d9c38166d9c74f89297aca79103ccfbd15b다. 현재 HEAD가 다르면 차이부터 확인하고 이미 고쳐진 문제는 다시 구현하지 마라. 줄 번호보다 함수명과 현재 코드를 신뢰해라.

- 기존 서재 미감과 책등 디자인, 기존 ID·상태·색·상징·인용문·감상, 작품당 한 기록 정책을 보존한다.
- 완독 전용 정책을 임의로 확장하지 않는다. 기존 reading/want 데이터는 삭제하거나 done으로 바꾸지 않는다.
- Supabase URL/공개 설정, 인증, 기존 storage key, JSON app/version 계약을 임의 변경하지 않는다. 비밀 키나 토큰을 출력하거나 커밋하지 않는다.
- 외부 API는 mock으로 검증한다. 실제 계정·책 데이터·공유 캐시를 테스트로 변경하지 않는다.
- 런타임 프레임워크 전환과 전면 재작성은 하지 않는다. 변경에 필요한 최소 의존성만 사용한다.
- 저장 실패 때 초안을 지우거나 성공 표시하지 않는다. 자동 화면 갱신은 입력·초점·스크롤을 보존한다.

- 변경 전 git status로 사용자 작업을 확인하고 덮어쓰지 않는다. 안전한 작업 브랜치에서 단계별 커밋을 만든다.
- 관련 테스트와 수동 재현을 수행하고 못 한 것은 명시한다. 테스트만 통과시키기 위해 기능을 제거하지 않는다.
- 종료 시 docs/HANDOFF.md를 갱신한다. 답변은 변경 요약, 검증 결과, 남은 위험, 다음 작업으로 15줄 이내. 전체 코드 출력 금지.
```

## 7. 기능을 계속 추가할 때의 원칙

기능마다 아래 6항목을 먼저 적고 한 기능씩 구현한다. 현재 기능의 재사용 지점을 먼저 찾아 중복 구현을 피한다.

```text
추가 기능: [...]
사용자가 해결하려는 일: [...]
진입 위치와 최소 동선: [...]
저장할 데이터 / 화면에서만 쓸 상태: [...]
기존 데이터의 기본값·백업·동기화 영향: [...]
완료 조건 3개 / 이번에 하지 않을 것: [...]

현재 구조에 맞는 최소 변경으로 구현하고, 관계없는 화면과 로직은 변경하지 마라.
저장 필드를 추가하면 normalize·저장·백업·복원·동기화의 왕복 보존부터 검토해라.
필요한 필드만 명시적으로 추가하고 미확인 필드를 무조건 펼쳐 복사하지 마라.
스키마 변경은 이전 데이터 읽기, 새 기본값, 실패 시 복구, 이전 앱으로 돌아갈 때의 손실 가능성을 함께 문서화해라.
새 모듈은 실제 두 번째 사용처 또는 명확한 책임 경계가 있을 때 만든다.
```

후속 후보는 완독일/재독 이력, 여러 판본, 장기 휴지통, 계정별 데이터 분리다. 완독일을 도입할 때 기존 createdAt을 실제 완독일로 자동 간주하면 안 된다. 여러 판본은 현재 작품 중복 정책을 바꾸므로 작품과 판본 데이터 모델을 먼저 결정한다. 단순히 중복 검사만 해제하지 않는다.
